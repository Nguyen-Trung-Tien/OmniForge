## Core Architectural & WinUI 3 Guardrails

- **[2026-11-01]** (WinUI 3 Navigation): `Frame.Navigate(Type)` instantiates `Page` classes via their parameterless constructor (`new Page()`). Never put required constructor parameters on a XAML `Page`; resolve `ViewModel` via `public MyViewModel ViewModel { get; } = App.GetService<MyViewModel>();`.
- **[2026-11-01]** (Zero-Touch Plugins): `ModuleAutoDiscoveryExtensions.AddDiscoveredToolModules` automatically registers any non-abstract `IToolModule`, its `ViewModelType`, `ViewType`, and co-located `I[Module]Service` -> `[Module]Service` in the same namespace. Never manually edit `ServiceCollectionExtensions.cs` when adding a new tool module.
- **[2026-11-01]** (C# 13 MVVM Toolkit): Always use C# 13 `public partial` properties with `[ObservableProperty]` (`public partial string InputText { get; set; }`) instead of legacy `private string _inputText;` fields to avoid MVVMTK0045 warnings under `<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`.
- **[2026-11-01]** (Atomic Settings Persistence): `LocalSettingsService` writes to `settings.json.tmp` and uses `File.Move(..., overwrite: true)` to guarantee atomic persistence and prevent corrupting user settings on sudden process termination.
- **[2026-11-01]** (Root CLI Workflow): Always execute builds, tests, scaffolding, and verification from the solution root using `.\forge <command>` (`verify`, `build`, `run`, `test`, `arch`, `new-module`, `new-test`, `learn`, `logs`, `doctor`) to avoid directory hopping and reduce agent token consumption.

- **[2026-11-01 11:49]** (Localization): Always use string.Create(CultureInfo.InvariantCulture, ...) when formatting numeric metrics (bytes, durations, percentages) so tests and UI remain deterministic on non-US locales like vi-VN.
- **[2026-11-01 17:19]** (WinUI3): EmptyStateControl.IsEmpty is a bool DependencyProperty and converts to Visibility internally; never attach BoolToVisibilityConverter to EmptyStateControl.IsEmpty or it will throw InvalidCastException (Visibility to Boolean) at runtime.
- **[2026-11-02 11:11]** (WinUI3): WinUI 3 does not provide a native AccentSplitButtonStyle theme resource (unlike Button AccentButtonStyle); do not set Style on SplitButton unless defining a custom Style in XAML.
- **[2026-11-02 20:20]** (Packaging & Release): In unpackaged self-contained WinUI 3 publish (`WindowsPackageType=None`), dotnet publish omits compiled XAML (`.xbf`) and the app's PRI file (`resources.pri` / `<AppName>.pri`). An explicit MSBuild target (`CopyWinUIResourcesToPublishDir`) is required in the App `.csproj` to copy `.xbf` files and `.pri` (as both `<AppName>.pri` and `resources.pri`) to `$(PublishDir)`. Without these, the installed app crashes immediately on startup with `XamlParseException: Cannot locate resource from 'ms-appx:///Views/MainWindow.xaml'` (HResult 0xc000027b).
- **[2026-11-02 21:15]** (WinUI 3 Navigation & Startup Lifecycle): In IoC/DI composition roots where `MainWindow` depends on `MainWindowViewModel`, DI creates `MainWindowViewModel` before `MainWindow`. ViewModels must never trigger navigation or attempt to navigate `INavigationService` inside their constructor because `Frame` has not yet been initialized by `MainWindow` (`Initialize(ContentFrame)`). Always defer initial module restoration to an explicit method (e.g. `RestoreInitialSelectionAsync`) called by `MainWindow` after `navService.Initialize(ContentFrame)` is complete. Wrap navigation and property updates in `IDispatcherService.TryEnqueue` to prevent cross-thread COM exceptions.
- **[2026-11-02 21:25]** (Agent Skills Architecture): Every new skill created in OmniForge must adhere to the 4-part directory structure (`SKILL.md`, `scripts/`, `examples/`, `resources/`) located under `.agents/skills/` (Antigravity standard, backwards compatible with `.agent/skills`). Agents MUST read official skill documentation at https://antigravity.google/docs/skills/ prior to skill creation, and propagate updates into `.agents/AGENTS.md` and related usage references. New skills can be quickly scaffolded via `.\forge new-skill <Name>`.
- **[2026-11-02 21:32]** (Issue Distillation): Created `issue-skill-distiller` skill (`.agents/skills/issue-skill-distiller`) and CLI task `.\forge distill-issue <Name>` to autonomously package solved bugs, symptoms, root causes, and verification steps into standardized Antigravity skills.
